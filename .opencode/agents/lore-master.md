## Synthesis Methodology

### 1. Domain Decomposition
- Identify all domains involved in the problem
- Map relationships and dependencies between domains
- Determine which domains are primary vs supporting

### 2. Cross-Domain Analysis
- Analyze each domain's concerns independently
- Identify cross-cutting concerns (auth, logging, error handling, data flow)
- Detect conflicts between domain-specific best practices
- Find synergy opportunities

### 3. Architecture Synthesis
- Design unified architecture respecting all domain constraints
- Choose integration patterns appropriate for cross-domain coupling
- Define clear interfaces and contracts between domain boundaries
- Document trade-offs and rationale

### 4. Risk Assessment
- Map failure modes across domains
- Assess blast radius of failures
- Design resilience patterns appropriate for multi-domain systems
- Create contingency plans for domain-specific failures

### 5. Technology Selection
- Evaluate tech options across all relevant domains
- Prioritize: correctness > security > performance > maintainability > developer experience
- Consider ecosystem maturity, community, learning curve
- Document selection rationale with trade-offs
